# LLLM 経理 仕様書・ロードマップ

## コンセプト

**日本の経理を学ぶための、ローカル LLM 付き学習サイト。**

- 直感的に「学びたいこと」を学べる総合サイト（簿記の基本 → 日々の経理 → 決算 → 税務 → 会計基準）
- 仕訳は教科書と同じ **仕訳形式（借方 / 貸方）** で画面に表示し、動かして確かめられるインタラクティブな UI にする
- 会計基準・税制が変わっても更新できるよう、**学習内容はコードから分けたデータ**（Markdown / YAML）で持ち、
  それぞれに「根拠（基準・法令）」と「基準日（いつ時点の内容か）」を持たせる
- ブラウザの中で動くローカル AI（LiteRT-LM + Gemma 4 など）が、見ている内容の解説・操作へのリアクション・質問への回答をする

## 基本方針

- **LLM にすべてを判断させない。** 仕訳の正誤・貸借の一致・集計（元帳・試算表・決算書）・税額の計算はプログラムが行い、
  LLM はその上に乗ってリアクション・解説・一緒に悩む・チャットでの掘り下げを担当する
- **アプリと LLM は構造化データでつなぐ。** 見ているレッスン・問題・自分の答えと採点結果・帳簿の状態を JSON にして渡す。
  必要なときは LLM がツール（関数呼び出し）でプログラムに問い合わせる（勘定科目の検索・仕訳の検証・税額の計算など）
- **LLM の性格タイプをユーザーが選べる**（先輩・先生・コーチ・ねこ部長・執事・カスタム）
- **ローカル AI で足りない処理は外部 AI に。** アプリがプロンプト（仕様と条件）を作り、ChatGPT・Claude・Gemini などに作ってもらった
  データ（レッスン・問題）を取り込む
- 既存のライブラリを積極的に使い、将来の拡張性・保守性を重視する
- 作って公開 → 確認 → 改善を小さく繰り返す（PR 単位でフェーズを進め、CI が通ったら main へマージ）

## UI / デザイン

- スマホ・PC 両対応（`md` = 768px 未満をスマホレイアウト）
  - スマホ: 画面下部にナビゲーションバー（ホーム / 学ぶ / 練習 / 帳簿 / AI / 設定）
  - PC: 左サイドバー（メイン 5 項目＋勘定科目・AI モデル・設定・ヘルプ）
- **アプリヘッダー**: ページ名・ページごとの操作・**ダークモード切り替え**・**ヘルプ**のアイコン（全ページ・全画面幅）
- GitHub へのリンクアイコンはヘッダーに置かない。リポジトリへのリンクはヘルプページのみ。
  GitHub のリリース履歴へのリンクはアプリのどこにも置かない
- ダークモードは落ち着いた配色（青みのないグレー・彩度を抑えたアクセント。[LLLM Study の DARK_THEME.md](https://github.com/MasakiNiwa/LLLM-Study/blob/main/docs/DARK_THEME.md) と同じ作り）。
  配色は「落ち着いたグレー（既定）/ あたたかいグレー / 鮮やか」から選べる
- アクセントカラーは落ち着いた青緑（帳簿・お金のイメージ）。借方・貸方は色だけでなく文字（借 / 貸）でも区別する

## アーキテクチャ

```
┌──────────────── メインスレッド（UI） ─────────────────┐     ┌──── Engine Worker（classic） ────┐
│ React + Zustand + wouter（ハッシュルーティング）       │     │ @litert-lm/core（WebGPU / Wasm）  │
│  pages/      ホーム・学ぶ・練習・帳簿・AI …           │ ⇄  │  Engine / Conversation            │
│  features/   learn, drill, ledger, chat, ai …         │     │  ツール呼び出しのループ           │
│  lib/journal 仕訳の解析・検証・採点（純粋関数）        │     │  OPFS へのモデル保存              │
│  lib/ledger  元帳・試算表・決算書の集計（純粋関数）    │     └───────────────────────────────────┘
│  lib/content 学習データの型（zod）と読み込み           │     ┌──── Search Worker ────────────────┐
│  lib/db      IndexedDB（Dexie）                        │ ⇄  │ 全文検索（MiniSearch・2-gram）    │
│  lib/llm/client.ts ── Comlink                          │     └───────────────────────────────────┘
└────────────────────────────────────────────────────────┘
        ▲ fetch（JSON）
┌───────┴──────── 学習データ（content/ → ビルド時に検証して public/content/ へ） ────────┐
│ tracks.yaml（分野）・lessons/**/*.md（レッスン）・accounts.yaml（勘定科目）            │
│ drills/*.yaml（仕訳問題）・rules/*.yaml（税率など、適用開始日つき）                     │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- **重い処理は Worker**: LLM の読み込み・推論・ダウンロードは Engine Worker、全文検索の索引づくりは Search Worker
- **GPU**: LLM は WebGPU で動かす（使えない端末では CPU の Wasm にフォールバック。学習機能はモデルなしで全部使える）
- **PWA**: ホーム画面に追加でき、オフラインでも起動できる（更新はユーザーが選ぶ）

### 学習データ（会計基準・税制の変更に追従するために）

学習内容はすべて `content/` のデータファイルで、コードを変えずに追加・更新できる。

| ファイル                      | 内容                                                                    |
| ----------------------------- | ----------------------------------------------------------------------- |
| `content/tracks.yaml`         | 分野（トラック）の一覧と表示順                                          |
| `content/lessons/<分野>/*.md` | レッスン。先頭に YAML（id・題名・分野・順番・レベル・根拠・基準日など） |
| `content/accounts.yaml`       | 勘定科目のマスタ（区分・表示区分・増える側・説明・別名・例）            |
| `content/drills/*.yaml`       | 仕訳問題のセット                                                        |
| `content/rules/*.yaml`        | 税率など、適用開始日・終了日つきの値（計算で日付に応じて選ぶ）          |
| `content/scenarios/*.yaml`    | 帳簿のサンプル（一連の取引）                                            |

- 各レッスン・問題セットは `basis`（根拠となる基準・法令）と `asOf`（内容の基準日）を持ち、画面に表示する。
  改正があったら、該当ファイルを直して `asOf` と `updated` を更新する（`changes` に変更の記録を残せる）
- ビルド時（`build/vite-plugin-content.ts`）に zod で形を検証し、**仕訳は貸借の一致と勘定科目の存在までプログラムで確かめる**。
  CI でも `npm run content:check` で検証する
- 外部 AI で作ったデータ（フェーズ 4）も同じ形式で、端末の IndexedDB に保存して同じ画面で使う

### レッスンの書き方（Markdown の拡張）

- ` ```shiwake ` … 仕訳。1 行に `借方科目 金額 / 貸方科目 金額`（片側だけの行も可）。`#` で始まる行は見出し（取引の説明）
- ` ```quiz ` … 確認問題（YAML。選択問題・仕訳問題）。答えはプログラムが採点する
- `> [!POINT]` / `> [!NOTE]` / `> [!WARNING]` / `> [!TIP]` … 囲み（ポイント・補足・注意・コツ）

### 仕訳の採点（プログラム）

- 借方・貸方それぞれで、同じ勘定科目の金額をまとめてから比べる（行の順番・分け方は問わない）
- 結果は「正解 / 貸借が一致していない / 科目が違う / 金額が違う / 借方と貸方が逆」などに分類し、
  どの行がどう違うかを返す（AI のリアクションや解説にもこの結果を渡す）
- 勘定科目は別名（例: 「売掛け」「売掛」→ 売掛金）でも受け付ける

### AI（LLM が上に乗る部分）

- **ペルソナ**: 口調・性格（システムプロンプト用）と、モデルがなくても出せる「ひとこと」のテンプレート
- **フロート解説**: レッスン・問題・帳簿の画面に AI ボタンを浮かべ、押すと見ている内容（構造化データ）を渡して解説。
  「この仕訳を解説」「具体例を出して」「一緒に考えて」などの定型の頼み方と、自由な質問
- **リアクション**: 問題の採点結果（プログラムが判定）に、性格に合わせたひとこと
- **チャット**: 送信のたびにアプリの状態を `<app_state>` の JSON にして付ける。ツール（勘定科目の検索・仕訳の検証・
  消費税の計算・レッスンの検索・学習の進み具合・帳簿の集計）をプログラムが実行して返す
- **モデルの保存**: [共通モデル保存仕様](SHARED_MODEL_STORAGE.md)に従い、同じ github.io のほかのサイト
  （LLLM Study・Try Local など）が保存したモデルも一覧に出して使える。端末のファイルとしてバックアップ・復元もできる

### データの保存

| 保存先       | 名前                  | 内容                                                       |
| ------------ | --------------------- | ---------------------------------------------------------- |
| localStorage | `lllm-keiri:settings` | 設定                                                       |
| IndexedDB    | `lllm-keiri`          | 学習記録・問題の結果・帳簿の仕訳・チャット・取り込んだ教材 |
| OPFS（共通） | `shared-models/`      | AI モデル（同じ github.io のサイトで共有）                 |

## ロードマップ

1 フェーズ = 1 PR（CI が通ったら main へマージ → GitHub Pages に公開）。公開して確かめ、次の改善点を見つけて次へ進む。
AI 側の利用制限（5 時間の枠など）にかからないよう、1 フェーズは数時間で終わる大きさにする。

### フェーズ 0: 土台（v0.1） ✅

- 仕様書・ロードマップ
- Vite + React + TypeScript + Tailwind、PWA、GitHub Pages へのデプロイ、CI（ライセンス・整形・lint・型・テスト・ビルド）
- 画面の骨組み（スマホの下部ナビ・PC のサイドバー・ヘッダーのダークモード切り替えとヘルプ）
- 設定（テーマ・ダークモードの配色・文字の大きさ・データのクリア）
- ヘルプ（リポジトリへのリンク・クレジットとライセンスの全文）

### フェーズ 1: 学習データとレッスン（v0.2） ✅

- 学習データの仕組み（`content/`・ビルド時の検証・基準日と根拠の表示）
- 仕訳の解析と表示（仕訳形式の表・貸借の合計）
- レッスン一覧（分野ごと）・レッスン画面（目次・前後のレッスン・読んだ印）
- 全文検索（Search Worker）
- 勘定科目の辞典
- 最初のレッスン: 簿記の基本（簿記とは・5 要素・仕訳のルール・取引の 8 要素・勘定と転記・試算表 など）

### フェーズ 2: インタラクティブな練習と帳簿（v0.3） ✅

- 仕訳問題（科目を選ぶ・金額を入れる → プログラムが採点・違いを表示・解説）
- レッスン内の確認問題（` ```quiz `）
- 帳簿（自分で入れた仕訳から総勘定元帳・試算表・貸借対照表・損益計算書を自動で作る。サンプルの取引も読み込める）
- 学習記録（読んだレッスン・問題の正答）とホームの「続きから」

### フェーズ 3: ローカル AI（v0.4） ✅

- AI モデル（LiteRT-LM・Gemma 4 E2B / E4B の Web 版。共通モデル保存領域・他サイトのモデルの認識・端末へのバックアップ）
- ペルソナ（性格タイプ）の選択
- フロート解説（見ている内容を構造化データで渡す）・問題へのリアクション
- チャット（アプリの状態の共有・ツール呼び出し・クリア）・ヘルプをもとに使い方に答える

### フェーズ 4: 外部 AI との連携（v0.5）

- 外部 AI に渡すプロンプトの作成（レッスン・問題セットの形式の仕様と条件を含める）
- 返答（JSON / Markdown）の取り込み・検証・管理（マイ教材）
- ローカル AI で難しい質問を、アプリの状態を添えたプロンプトにして外部 AI に聞く

### フェーズ 5 以降（候補）

- 学習内容の拡充: 商業簿記 3 級 → 2 級、日々の経理実務（経費精算・請求書・入金消込・給与・源泉徴収）、
  決算（決算整理・減価償却・引当金・経過勘定）、消費税（インボイス制度・税込 / 税抜経理）、法人税の基本、
  電子帳簿保存法、会計基準（収益認識・リース・減損・税効果・連結）
- 間違えた問題の復習（FSRS などの間隔反復）
- 財務諸表の読み方・分析（比率の計算はプログラム、解説は AI）
- 帳簿のシナリオ（1 か月の取引を順に入れて決算まで）
- AI の音声読み上げ、レッスン中の用語のポップアップ
